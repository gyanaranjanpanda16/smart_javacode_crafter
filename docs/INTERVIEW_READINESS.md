# Interview readiness

Score each dimension 0–2 after a mock: 0 = missing or incorrect, 1 = achieved with prompts, 2 = independent and clearly justified. These are self-assessment targets, not company hiring cutoffs.

| Coding | LLD | HLD |
| --- | --- | --- |
| Clarifies inputs and constraints | Clarifies scope and use cases | Defines scope and SLOs |
| Derives approach/invariant | Defines entities and invariants | Estimates QPS/storage with units |
| Writes correct readable Java | Separates responsibilities | Connects APIs, schema and components |
| Tests edge cases and complexity | Implements/tests key behavior | Handles bottlenecks and failures |
| Communicates and adapts | Handles change/concurrency | Defends alternatives and costs |

Aim for at least 8/10 in each relevant track over three recent mocks, with no zero on correctness or failure handling. Use an unseen problem and a partner when possible. Record actual elapsed time, hints, failed cases, and one repair exercise.

## Behavioral preparation

Prepare six true STAR stories: ownership, conflict, failure, ambiguity, collaboration, impact. Explain your individual contribution, technical decision, alternative considered, result, and learning. Practice a concise project walkthrough and a deeper architecture discussion.

## Weekly retrospective

- What could I solve without help?
- Which invariant or concept did I misunderstand?
- What repeated mistake will next week address?
- Which delayed reviews are still due?
- What is the smallest concrete next step?
